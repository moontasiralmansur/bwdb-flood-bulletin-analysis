# BWDB Flood Bulletin Analysis

A Python project that extracts river water-level data from Bangladesh Water Development Board (BWDB) flood bulletins in PDF, validates and cleans it, and runs statistical analysis: sampling, probability, exploratory data analysis, and bulletin comparison.

## Project Overview

BWDB Flood Bulletin Analysis is a data pipeline that converts official flood river-monitoring bulletins from the Bangladesh Water Development Board into analysis-ready datasets and applies statistical methods to them.

The pipeline takes two PDF bulletins as input, extracts and validates the station data, and produces cleaned Excel datasets, analysis tables, sample files, EDA figures, and a Markdown analysis report.

The main steps are:

1. **Extraction:** PDF text is extracted line by line, station rows are identified and parsed into typed fields.
2. **Validation and cleaning:** Records are validated, cleaned, and enriched with basin membership recovered from the bulletin headings.
3. **Analysis:** The cleaned datasets feed sampling (simple random, systematic, stratified), probability analysis, exploratory data analysis, and a comparison of the two observation periods.
4. **Reporting:** Results are exported as Excel tables, sample files, PNG figures, and a Markdown report.

## Dataset Overview

- **Source files.** Two BWDB river situation bulletins (`dataset1.pdf`, `dataset2.pdf`) and a column-description PDF in `data/raw/`.
- **Observation times.** 20-07-2026 at 09:00 (dataset1) and 15:00 (dataset2).
- **Cleaned datasets.** `data/processed/dataset1_clean.xlsx` and `dataset2_clean.xlsx`, 128 records and 14 columns each, generated by `main.py`.
- **Basin enrichment.** A `basin` column is added at analysis time from the basin headings printed in the bulletins (BRAHMAPUTRA, GANGES, MEGHNA, SOUTH EASTERN HILL).
- **Statistical analysis.** Sampling (simple random, systematic, stratified), empirical probability analysis, numerical and visual EDA, and a 09:00 vs 15:00 bulletin comparison.

The full schema and column details are documented in `docs/dataset-specification.md`.

Known characteristics of the source bulletins (documented in full in `docs/dataset-specification.md`):

- **Duplicate serial 49.** The 15:00 bulletin (dataset2) assigns serial 49 to two different stations.
- **CHANDPUR continuation row.** One station is split into two rows; the continuation row has no serial number and is kept as its own record.
- **Missing values preserved.** Unavailable values are printed as `-` in the bulletin and preserved as missing (NaN) in the data.
- **Basin metadata recovered from headings.** Basin membership is implicit in the document layout and is reconstructed from the printed basin headings.
- **Underline formatting not recoverable.** Page 2 of each bulletin underlines several station rows with drawn rules; text extraction does not capture this formatting, so it is not represented in the data.

These are properties of the source documents, not parser defects.

## How to Run

1. Create and activate a virtual environment, then install dependencies:

   ```
   python -m venv .venv
   .venv\Scripts\activate        # Windows
   source .venv/bin/activate     # macOS / Linux
   pip install -r requirements.txt
   ```

2. Place the BWDB bulletins in `data/raw/` (`dataset1.pdf`, `dataset2.pdf`).

3. Run the pipeline for both datasets:

   ```
   python main.py
   ```

   This extracts, parses, validates, cleans, and exports both datasets to `data/processed/`, and prints an execution summary with cross-validation results.

4. Generate the analysis artifacts:

   ```
   python src/report.py
   ```

   This produces the tables, samples, and Markdown report under `outputs/` (requires the processed datasets from step 3). Individual phases can also be run standalone, e.g. `python src/eda.py` for the figures.

## Limitations

- **Layout-specific parser.** The row grammar, header patterns, and classification rules encode the current BWDB bulletin format; a changed layout would require parser updates.
- **Dependence on BWDB bulletin formatting.** The pipeline assumes character-spaced columns, dashed separators, and one data row per physical line, all verified for the current bulletins.
- **Missing values originate from source documents.** RHWL (19 stations) and danger levels (4 stations) are absent from the bulletins and are not imputed.
